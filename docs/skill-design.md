## 一、引擎能力速查（设计前必读）

### 1.1 兵种代号 `cls`

| 代号 | 兵种 | 特性 |
|---|---|---|
| `inf` | 步兵 | 基础兵种，克炮兵 |
| `art` | 炮兵 | 射程 2，攻击不受反击 |
| `tank` | 装甲 | 克炮兵，碾压步兵 |
| `air` | 轰炸机 | 飞行，无视地形与 ZOC，攻击不受反击 |

### 1.2 已支持的 10 种技能效果

| 写法 | 效果 | 界面显示 |
|---|---|---|
| `{ k:'atk', m:0.25 }` | 攻击力 +25%（可加 `cls` 限定兵种） | `装甲·攻击力 +25%` |
| `{ k:'def', m:0.30 }` | 防御力 +30%（可加 `cls` 限定兵种） | `防御力 +30%` |
| `{ k:'mov', n:2 }` | 移动力 +2（可加 `cls` 限定兵种） | `装甲·移动力 +2` |
| `{ k:'nozoc' }` | 无视敌方控制区（ZOC） | `无视敌方控制区` |
| `{ k:'rng', n:1 }` | 炮兵射程 +1 | `炮兵射程 +1` |
| `{ k:'counter', m:0.30 }` | 反击伤害 +30% | `反击伤害 +30%` |
| `{ k:'citydef', m:0.40 }` | 驻守城市时防御 +40% | `驻守城市防御 +40%` |
| `{ k:'vs', tgt:'art', m:0.40 }` | 对指定兵种伤害 +40% | `对炮兵伤害 +40%` |
| `{ k:'aura', m:0.10 }` | 相邻友军攻击 +10%（光环） | `相邻友军攻击 +10%（光环）` |
| `{ k:'rage' }` | 兵力低于 50% 时攻击 +15%（固定值） | `兵力低于50%时攻击 +15%` |

**数值标尺**（现有 23 位将领的取值范围，设计时不要大幅越界）：
攻击/防御加成 10%–30%，对特定兵种克制 15%–40%，移动力 +1~+2，城市防御 40%–50%。
`rage` 的 +15% 是引擎写死的，`aura`/`atk` 等的 `m` 自己给值。

### 1.3 设计陷阱：写了不生效或无意义的组合（务必避开）

以下组合**数据合法、界面也会照常显示文字，但引擎里不生效或没有意义**。
这是引擎的历史限制，修复前（见待办池的引擎提案）不要使用：

| 陷阱 | 现象 | 引擎原因 |
|---|---|---|
| `aura` 写了 `m` 值 | 界面按 `m` 显示，实际固定 +10% | `game.js effAtk` 写死 `m *= 1.1`，不读 `s.m` |
| `rage` 写了 `m` 值 | 界面按 `m` 显示，实际固定 +15% | `effAtk` 写死 `m *= 1.15`，不读 `s.m` |
| 非炮兵写 `rng` | 显示"炮兵射程+1"，实际无效 | `targetsOf` 中非炮兵攻击距离恒为 1 |
| 炮兵/空军写 `counter` | 显示"反击伤害+X%"，实际无效 | 反击仅由步兵/装甲防守方打出 |
| 空军写 `nozoc` | 显示"无视控制区"，实际冗余 | 空军移动本就无视 ZOC 与地形 |

> 反例（合法且有效）：`vs { tgt:'air' }` —— 克制表里空军是普通攻击目标，
> 这正是"防空专家"类技能的实现方式（蒙哥马利的对空军克制即由此实现）。

### 1.4 数据格式（generals.js 里的一条记录）

```js
{ id: 'rommel', name: '隆美尔', ct: 'de', title: '沙漠之狐',
  face: { hat: 'peak', acc: 'goggles' },   // 头像形象：大檐帽+风镜
  skills: [{ k: 'atk', cls: 'tank', m: 0.20 }, { k: 'vs', tgt: 'art', m: 0.40 }, { k: 'rage' }],
  bio: '一句到两句的史实小传，面板里直接展示。' },
```

- `ct` 国家代号见 `js/data/nations.js`（`de`德 `su`苏 `uk`英 `us`美 `fr`法 `it`意…）
- `face` 头像形象（`ui.js genPortrait` 渲染）：`hat` 六选一
  （peak大檐帽 / steel钢盔 / beret贝雷帽 / pilot飞行皮帽 / ushanka苏军棉帽 / bush船形帽），
  可选 `acc`（goggles风镜 / star将星，将星苏军红他国金）；按史实形象选择，
  右下角技能徽记（兵种字/盾/★）由 skills 自动推导，改技能自动同步
- 每人 `skills` 建议 1–3 条，贴合史实"看家本领"，避免堆数值
- 将领名册按 `cf[ct]` 归入轴心/同盟/苏联三阵营招募池

### 1.5 相关机制（设计技能时可以借力）

- 伤害公式 `42 × 攻/(攻+防)`，兵力越低输出越弱 → 攻防加成边际收益递减
- 兵种克制：坦克克炮 140%，步兵克炮 130%、怕坦克 65%，空军怕高射炮
- 老练度：XP 100/250/450 → 3 级，每级攻防 +8%；将领击杀 3 人升 1 星（≤5 星），每星攻防 +4%
- 驻防 +30% 防御（可与 `citydef` 叠加讨论）

## 三、设计提案模板

新增/调整技能时，复制下面的模板填好，经讨论定稿后落入 `generals.js`：

```markdown
### 提案：<将领名>（<阵营>）
- **史实依据**：他/她最出名的一件事，以及它如何转译成技能
- **技能组**（1–3 条）：
  1. `技能写法` —— 设计意图一句话
  2. …
- **强度自评**：对标现有哪位将领？为何不会过强/过弱？
- **对局影响**：会改变哪类打法？（速攻/防守/空降…）
```

## 四、协作流程

1. 在 `feature/skill-design` 分支上改 `js/data/generals.js` + 更新本文档
2. 本地双击 `index.html` 试玩验证（或 `node test_logic.js` 跑数据校验）
3. 提交并推送，到 GitHub 发 Pull Request 到 `main`，让伙伴审核合入
4. 重大机制类想法（新 effect 类型）先在这里写提案，再开 issue/PR 讨论

```bash
git checkout feature/skill-design
git pull                      # 开工前同步
# …修改 generals.js 与本文件…
git add -A && git commit -m "技能设计：<一句话说明>"
git push                      # 首次推送用 git push -u origin feature/skill-design
```
